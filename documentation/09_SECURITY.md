## 1. Security Architecture

### 1.1 Threat Model

```
                         ┌───────────────┐
                         │   External    │
                         │  AI Model     │
                         │  APIs (HTTPS) │
                    ┌────┴───────────────┴────┐
                    │   Internet Boundary      │
                    └────┬───────────────┬────┘
                         │               │
              ┌──────────▼──────┐  ┌────▼──────────┐
              │ OpenClaw Gateway│  │ Model Provider │
              │ (localhost:18789│  │ (Claude, GPT)  │
              └──────────┬──────┘  └───────────────┘
                         │ WebSocket (local)
              ┌──────────▼──────────────┐
              │     Axtrizen App        │
              │  ┌────────┬──────────┐  │
              │  │ Rust   │ WebView  │  │
              │  │Backend │ Frontend │  │
              │  └───┬────┴──────────┘  │
              │      │                  │
              │  ┌───▼──────────────┐   │
              │  │  SQLite DB       │   │
              │  │  (~/.axtrizen/)  │   │
              │  └──────────────────┘   │
              └─────────────────────────┘
```

### 1.2 Trust Boundaries

| Boundary               | Trust Level   | Controls                        |
| ---------------------- | ------------- | ------------------------------- |
| **User ↔ App**         | Trusted       | macOS Gatekeeper, code signing  |
| **Frontend ↔ Backend** | Sandboxed     | Tauri IPC allowlist             |
| **App ↔ Gateway**      | Local trusted | Token auth, localhost-only      |
| **Gateway ↔ Internet** | Untrusted     | HTTPS, API keys, token rotation |

## 2. Data Security

### 2.1 Data at Rest

| Data              | Storage                   | Encryption                | Sensitivity |
| ----------------- | ------------------------- | ------------------------- | ----------- |
| User settings     | SQLite (`settings` table) | None (local file)         | Low         |
| Chat history      | SQLite (`chat_messages`)  | None (local file)         | Medium      |
| Agent configs     | Gateway workspace files   | None (filesystem)         | Medium      |
| Project workspace | `~/.axtrizen/projects/`   | None (filesystem)         | Medium      |
| API keys/tokens   | OpenClaw config file      | OS keychain (recommended) | High        |
| Database file     | `~/.axtrizen/axtrizen.db` | None (single-user local)  | Medium      |

### 2.2 Data in Transit

| Path               | Protocol  | Encryption              |
| ------------------ | --------- | ----------------------- |
| Frontend ↔ Backend | Tauri IPC | In-process (no network) |
| App ↔ Gateway      | WebSocket | None (localhost)        |
| Gateway ↔ AI APIs  | HTTPS     | TLS 1.2+                |

### 2.3 Sensitive Data Handling

| Data Type         | Policy                                                   |
| ----------------- | -------------------------------------------------------- |
| AI model API keys | Stored in OpenClaw config; never exposed to frontend     |
| Gateway token     | Fetched from config; stored in Rust state (not frontend) |
| Chat contents     | Persisted locally; no cloud sync                         |
| Generated code    | Written to workspace; user-controlled                    |

## 3. Authentication & Authorization

### 3.1 Gateway Authentication

```
App startup → get_gateway_token() → Token from OpenClaw config
           → gateway_connect(url, token) → WebSocket handshake
           → Token validated by Gateway → Connection established
```

**Token Lifecycle:**

- Tokens are generated by OpenClaw during device registration
- Stored in `~/.config/openclaw/` config file
- Never transmitted over public internet
- No expiration (local-only usage model)

### 3.2 Device Management

| Command          | Description                 |
| ---------------- | --------------------------- |
| `device_list`    | List all registered devices |
| `device_approve` | Approve a pending device    |
| `device_reject`  | Reject a device request     |
| `device_revoke`  | Revoke an approved device   |

### 3.3 IPC Security

Tauri's IPC is **allowlisted** — only commands registered in `lib.rs` are callable from the frontend. The frontend cannot execute arbitrary Rust code.

**Registered commands:** 65+ (see `lib.rs` line 25-158)

## 4. Application Security

### 4.1 Input Validation

| Input          | Validation                               |
| -------------- | ---------------------------------------- |
| Agent name     | Non-empty string                         |
| Team name      | Non-empty string                         |
| Project name   | Non-empty string                         |
| Chat message   | Non-empty, sanitized of protocol tags    |
| File paths     | Must be within workspace directory       |
| SQL parameters | Parameterized queries (no SQL injection) |

### 4.2 SQL Injection Prevention

All database queries use **parameterized statements**:

```rust
// ✅ Safe — parameterized
conn.execute(
    "UPDATE tasks SET status = ?1 WHERE id = ?2",
    params![status, id],
)?;

// ❌ Never done — string interpolation
// conn.execute(&format!("UPDATE tasks SET status = '{}' WHERE id = '{}'", status, id))?;
```

### 4.3 XSS Prevention

| Layer    | Protection                                      |
| -------- | ----------------------------------------------- |
| React    | JSX auto-escapes by default                     |
| Markdown | `react-markdown` sanitizes HTML                 |
| Chat     | Protocol tags stripped (`</final>`, `</error>`) |
| Tauri    | WebView sandboxed, no `eval()`                  |

### 4.4 File System Security

| Operation          | Constraint                               |
| ------------------ | ---------------------------------------- |
| Workspace creation | Scoped to `~/.axtrizen/projects/<uuid>/` |
| File writing       | Only within workspace path               |
| File reading       | `read_file_content` checks path exists   |
| Directory opening  | System file manager (no remote paths)    |

## 5. Network Security

### 5.1 Gateway Connection

| Aspect             | Policy                                   |
| ------------------ | ---------------------------------------- |
| **Protocol**       | WebSocket (ws://)                        |
| **Binding**        | localhost only (127.0.0.1:18789)         |
| **Authentication** | Token-based handshake                    |
| **Reconnection**   | Auto-reconnect with exponential backoff  |
| **Timeouts**       | Connection timeout: 5s; idle: indefinite |

### 5.2 External API Calls

| Aspect            | Policy                                           |
| ----------------- | ------------------------------------------------ |
| **Protocol**      | HTTPS only                                       |
| **Endpoints**     | API provider endpoints (api.anthropic.com, etc.) |
| **API Keys**      | Managed by OpenClaw Gateway                      |
| **Rate Limiting** | Provider-enforced                                |

## 7. Security Checklist

### Pre-Release

- [ ] All database queries use parameterized statements
- [ ] No hardcoded credentials in source code
- [ ] Gateway token read from config file, not environment
- [ ] `open_workspace` validates path is a directory
- [ ] `read_file_content` does not traverse outside workspace
- [ ] Frontend cannot invoke unregistered commands
- [ ] No `eval()` or `dangerouslySetInnerHTML` (except controlled markdown)
- [ ] WebSocket connection restricted to localhost

### Runtime

- [ ] Gateway token validation on every request
- [ ] Graceful handling of Gateway disconnection
- [ ] Error messages do not leak internal paths
- [ ] SQLite database has appropriate file permissions (600)

## 8. Known Limitations

| Limitation                 | Risk                          | Mitigation                           |
| -------------------------- | ----------------------------- | ------------------------------------ |
| No data encryption at rest | Low (local-only, single-user) | OS-level disk encryption (FileVault) |
| WebSocket without TLS      | Low (localhost-only)          | Future: wss:// for remote Gateway    |
| No audit logging           | Medium                        | Future: signed audit trail           |
| No RBAC                    | Low (single-user desktop app) | Future: role-based for multi-tenant  |
| API keys in config file    | Medium                        | Future: OS keychain integration      |
